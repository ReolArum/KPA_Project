# [KPA_Project] 탐사(Exploration) 시스템 아키텍처 및 구현 요약

탐사 시스템의 현재 구현 상태와 핵심 로직을 정리한 요약 문서입니다. 본격적인 추가 수정 작업에 들어가기 전 베이스라인으로 활용합니다.

---

## 🏗️ 1. 탐사 핵심 메커니즘 (Core Mechanics)

### **A. 경로 생성 방식 (Path Drawing)**
- **입력**: `ExplorationManager`에서 0번 마우스(좌클릭) 드래그를 감지합니다.
- **드로잉**: `Physics.Raycast`를 통해 바닥(`Ground` 레이어) 좌표를 실시간으로 추적하며 점들을 `pathSegments`에 추가합니다.
- **충돌 감지**: 드로잉 중 `Obstacle` 레이어를 가진 벽에 닿으면 즉시 그리기가 강제 중단되어 벽 너머를 그릴 수 없게 합니다.
- **지능형 연결**: 단일 클릭 또는 경로가 끊긴 상태에서 클릭 시, **Unity NavMesh**를 활용하여 마지막 지점부터 현재 지점까지의 최단 경로를 자동으로 계산하여 이어줍니다.
- **실행 취소(Undo)**: 마우스 우클릭 시 마지막으로 뗐던 드래그 구간(Segment)을 통째로 삭제합니다.

### **B. 페이즈 및 카메라 전환**
- **Planning (탑뷰)**: 맵을 수직으로 내려다보며 경로를 설계하는 단계입니다.
- **Moving (쿼터뷰)**: '경로 확정' 버튼 클릭 시 카메라가 부드럽게 대각선 시점(Quarter-view)으로 회전하며 이동이 시작됩니다.
- **Result (정산)**: 시간 초과나 탈출구 도달 시 결과 화면을 출력합니다.

---

## 📂 2. 데이터 흐름 및 저장 (Data & Persistence)

### **A. 관련 클래스 역할**
- **`ExplorationState.cs`**: 현재 세션의 임시 데이터(남은 시간, 수집 골드, 발견 단서, 경로 목록)를 보관합니다.
- **`ExplorationManager.cs`**: 입력 처리, NavMesh 계산, 이동 루틴 제어 등 시스템의 심장부입니다.
- **`ExplorationUIController.cs`**: HUD 업데이트, 경로 시각화(`LineRenderer`), 카메라 전환 코루틴, 이벤트 팝업 제어를 담당합니다.
- **`ExplorationStageData.cs`**: 맵의 노드 위치, 이벤트 내용, 시간 제한 등 스테이지별 고정 기획 데이터를 보관하는 ScriptableObject입니다.

### **B. 세이브 시스템 연동**
- 탐사가 **성공(`OnExplorationSucceeded`)**하거나 **실패(`OnExplorationFailed`)**하는 즉시 현재까지 획득한 골드와 아이템이 `GameState`에 반영되고 `SaveSystem.Save()`가 호출되어 영구 보존됩니다.

## 🛠️ 3. 현재의 한계 및 수정 예정 사항 (Next Steps)

1.  **아이템 시스템 연동**: 현재 선택지의 `HasItem` 체크 로직이 더미(`true` 반환) 상태입니다. 실제 인벤토리 데이터와 연결이 필요합니다.
2.  **UI 비주얼 강화**: 현재 프로토타입 수준의 `LineRenderer`와 HUD 디자인을 실제 아트 리소스에 맞춰 개선해야 합니다.
3.  **사운드 및 이펙트**: 이동 중 발소리, 벽 충돌 시 피드백, 이벤트 발생 시 사운드/이펙트 추가가 필요합니다.
4.  **노드 가시성**: `InteractiveHighlight`가 프로토타입 단계(컬러 변경)이므로, 프리팹 베이스의 아웃라인이나 고유 연출이 필요합니다.
