# [KPA_Project] 프로젝트 개발 지침 및 가이드라인

이 문서는 사용자가 지시한 모든 핵심 지침과 기획 요구사항을 통합하여 관리하는 공식 가이드입니다. 향후 개발 시 반드시 이 규칙들을 준수해야 합니다.

---

## 📂 1. 프로젝트 구조 및 파일 생성 규칙
-   **스크립트 관리**: 모든 새로운 스크립트는 `Assets/_Project/Scripts/` 하위의 관련 도메인 폴더(`Core`, `Systems`, `Data` 등)에 생성해야 합니다.
-   **문서 관리**: 모든 마크다운(`.md`) 파일은 프로젝트 루트의 **`Docs/`** 폴더 내에 위치해야 합니다.
-   **에디터 스크립트**: `UnityEditor` 관련 로직이 포함된 스크립트는 반드시 각 시스템 폴더 하위의 `Editor/` 폴더에 위치시켜야 합니다.

## 🕵️ 2. 탐사(Exploration) 시스템 핵심 메커니즘
-   **카메라 전환**: 
    -   시작 및 그리기 페이즈: **탑뷰(Top-view)**
    -   이동 및 실행 페이즈: **쿼터뷰(Quarter-view)** (부드러운 전환 효과 포함)
-   **경로 드로잉**: 
    -   마우스를 클릭한 상태로 **그림 그리듯 드래그**하여 연속적인 경로를 생성합니다.
    -   벽(`Obstacle` 레이어)에 닿으면 드로잉이 자동으로 중단됩니다.
-   **지능형 경로 연결**: 
    -   마우스를 단순히 클릭하거나 끊긴 구간에서 다시 클릭 시, **NavMesh**를 사용하여 이전 지점과 현재 클릭 지점 간의 **최단 경로**를 자동 생성합니다.
-   **실행 취소(Undo)**: **마우스 우클릭** 시 마지막으로 뗐던 지점까지의 경로 세그먼트를 삭제합니다.
-   **시각적 강조**: 상호작용 가능한 특수 오브젝트(상호작용 가능, 함정, 보상 등)는 탑뷰에서 **아웃라인**이나 **다른 색상**으로 강조 표시되어야 합니다.

## 💾 3. 데이터 및 저장 시스템 (Persistence)
-   **즉시 저장**: 탐사 성공(`OnExplorationSucceeded`) 또는 실패(`OnExplorationFailed`) 시 결과 데이터를 즉시 세이브 처리합니다.
-   **세이브 데이터 항목**: 시설 업그레이드 레벨, 일일 의뢰 리롤 여부, 훈련 효율, 어제 스케줄, 탐사 발견 오브젝트 목록을 누락 없이 저장해야 합니다.

## 📅 4. 게임 운영 및 스케줄링
-   **어제 스케줄 적용**: "어제와 동일하게" 버튼 클릭 시 이전 날의 스케줄을 현재 슬롯으로 복사하는 기능이 작동해야 합니다.
-   **스케줄 초기화**: 초기화 시 스탯 값은 `None`이 아닌 기본값인 **`Strength(힘)`**로 설정합니다.
